Insert / lookup cost, three implementations

The memory win has a latency cost — reported both directions.
Insert — declaring a new identifier (e.g. compiler sees int count;) and the table deciding how to store it and writing it in.
Lookup (hit) — code refers back to a name already declared (e.g. using count later) and the table finds it.
Lookup (miss) — code refers to a name that was never declared (a typo, or a real "undefined variable" error) and the table has to search and confirm it's absent.
Scope enter / exit — entering or leaving a { } block (a function, loop, or if-statement) — the table pushes or pops that block's names.

△
Memory-for-latency trade, not a strict win. BudgetSym's insert is consistently the slowest (more decision logic per symbol: budget check, scope/lifetime read, prefix comparison, frequency tracking) and lookup pays a hash-then-reconstruct path every entry uses. Conventional and Interned stay faster on both operations across all 8 datasets.
